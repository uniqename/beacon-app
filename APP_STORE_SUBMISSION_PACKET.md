## 🔒 Privacy Permissions Reference

### What these are
Every iOS app must declare **why** it needs access to sensitive device features.
Apple will **reject** or **crash** the app if a permission is used without a declaration.
These are stored in `ios/Runner/Info.plist` in the app code.

On Android the equivalent is in `AndroidManifest.xml` (permissions) and the
**Data safety** section in the Play Console (filled in manually — see below).

---

### iOS — All declared permissions (Info.plist keys)

#### 1. NSCameraUsageDescription
**What it is:** Permission to use the device camera.
**Why Beacon needs it:** Users can photograph documents/evidence for their case file and take profile photos.
**What to put (App Store Connect > Privacy):** "Users may photograph evidence for their case file, take profile pictures, and document incidents when requesting support."

#### 2. NSMicrophoneUsageDescription
**What it is:** Permission to record audio via the microphone.
**Why Beacon needs it:** Live audio support group rooms powered by Agora — users speak with counselors and peers.
**What to put:** "Required to speak in live audio support group sessions with counselors and peer supporters."

#### 3. NSPhotoLibraryUsageDescription
**What it is:** Permission to read photos from the camera roll / Photos app.
**Why Beacon needs it:** Users can upload existing photos for their profile or case documentation.
**What to put:** "Users may upload photos from their library for profile pictures and to document incidents for their support case."

#### 4. NSLocationWhenInUseUsageDescription
**What it is:** Permission to read GPS location while the app is open.
**Why Beacon needs it:** Finds nearby emergency services, shelters, and support resources.
**What to put:** "Used to find nearby emergency services, shelters, and support organisations when you request local help."

#### 5. NSLocationAlwaysAndWhenInUseUsageDescription
**What it is:** Same as above but also while the app is in the background.
**Why Beacon needs it:** Panic/emergency alert feature — location sent even if the user has switched away from the app.
**What to put:** "Needed for the emergency alert feature so your location can be shared with trusted contacts even when the app is in the background."

#### 6. NSFaceIDUsageDescription
**What it is:** Permission to use Face ID (or Touch ID via the `local_auth` package).
**Why Beacon needs it:** Optional biometric login — users can unlock the app without typing their password.
**What to put:** "Used to let you log back in securely with Face ID, protecting your sensitive support information."

#### 7. NSUserTrackingUsageDescription
**What it is:** iOS 14.5+ App Tracking Transparency — shown before any cross-app tracking.
**Why Beacon needs it:** The `app_tracking_transparency` package is linked (required by Firebase/analytics SDKs). Without this key the app crashes on iOS 17+.
**What to put:** "Beacon uses anonymous analytics only to improve app stability. No personal data is shared with advertisers or third parties."
**Note:** Beacon does NOT actually track users across apps. The key is required because the framework is linked. Users who deny tracking are unaffected.

### App Store Connect — Privacy Nutrition Label
*(Settings > App Privacy in App Store Connect)*

Fill in each section as follows:

| Data type | Collected? | Linked to identity? | Used for tracking? |
|---|---|---|---|
| Name | Yes | Yes | No |
| Email address | Yes | Yes | No |
| Phone number | Optional | Yes | No |
| Location (coarse) | Yes | No | No |
| Photos/videos | Yes | Yes | No |
| Audio data | Yes | No | No |
| User ID | Yes | Yes | No |
| Crash data | Yes | No | No |
| Performance data | Yes | No | No |

For every "Yes" row, select **"App Functionality"** as the purpose.
Leave **"Tracking"** unchecked for all rows — Beacon does not track across apps.

---

### Google Play — Data Safety Section
*(Play Console > App content > Data safety)*

Step by step:

1. **Does your app collect or share any of the required user data types?** → Yes
2. **Is all of the user data collected by your app encrypted in transit?** → Yes
3. **Do you provide a way for users to request that their data is deleted?** → Yes (account deletion is in Settings)

**Data types to declare:**

| Category | Data type | Collected | Shared | Purpose |
|---|---|---|---|---|
| Location | Approximate location | Yes | No | App functionality |
| Personal info | Name | Yes | No | Account management |
| Personal info | Email address | Yes | No | Account management |
| Personal info | Phone number | Optional | No | Account management |
| Photos and videos | Photos | Yes | No | App functionality |
| Audio | Voice/sound recordings | Yes | No | App functionality |
| App activity | App interactions | Yes | No | Analytics |
| App info and performance | Crash logs | Yes | No | Analytics |

4. For each row above: Collection = **Yes**, Required = **No (optional)** for most, Purpose = **App functionality**
5. Sharing = **No** for all rows
6. **Security practices:** Check "Data is encrypted in transit" and "You can request data deletion"

### When you add a new feature that uses device hardware
If you ever add a feature that uses a new permission (e.g. Bluetooth, Contacts, Calendar),
you must do **all three**:
1. Add the `NS___UsageDescription` key to `ios/Runner/Info.plist`
2. Add the `<uses-permission>` line to `android/app/src/main/AndroidManifest.xml`
3. Update the App Store Connect Privacy Nutrition Label and Google Play Data Safety section

Missing any one of these causes App Store rejection or a crash on newer iOS versions.
